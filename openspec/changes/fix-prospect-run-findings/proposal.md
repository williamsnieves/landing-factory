# Proposal: fix-prospect-run-findings

## Why

The two fisioterapia-ribera runs (the first prospect test, 2026-11-04, PR #55, and the rebuild on `calm-statement`, 2026-11-06, PR #60) left small problems in the prospect flow and the checks. Each one cost a manual step or gave the agent a wrong signal:

- **The sales kit is skipped.** Both runs ended `Result: passed` without `SALES.md`: the skill's last step (`prospect.mjs kit`) was not run, and the kit was written by hand twice. When it is written, the file is not Prettier-formatted, so `prettier --check` fails until someone formats it.
- **The kit describes the plan, not the page.** "What was built" copies the proposal's "Archetype blend" bullets, including "Planned deviations", and does not say what the build actually chose (palette, fonts, hero, the signature moment as built). Its image rule still says "Wikimedia Commons or The Met", which is out of date since Pixabay and imported Pexels photos are allowed for prospects.
- **The skip link counts as a button.** `layout-signature.mjs` measures every visible `a`, `button` or `[role="button"]` with a background. The off-screen skip link of `BaseLayout` (`Skip to content`) has a filled background, so it counted as a filled rectangular button; to get past `layout-diversity` the first build turned the approved filled call-to-action button into a text link.
- **Duplicated `_headers` blocks are not reported.** The first prospect build wrote a second `/*` block in `dist/_headers`; Cloudflare Pages served only one of them and the security headers disappeared. The static report merged both blocks (as the format describes) and passed; only the live report caught it.

## What Changes

- **Kit at the end of every prospect build.** `scripts/new-landing.sh`, after a `passed` result with `--auto` (the same place it runs `check-landing`), runs `node scripts/prospect.mjs kit --site <slug>` when the brief has `prospect.status: "prospect"`; a kit error fails the run. The skill keeps its own step, so a run that writes the kit itself is unchanged (the script overwrites it with the same text).
- **Kit formatted.** `writeKit` formats `SALES.md` with the repository's Prettier before writing it (the same way the export formats its output), so `prettier --check` passes.
- **Kit describes the built page.** "What was built" lists the primary, secondary and lent traits of the blend from `PROPOSAL.md` without the "Planned deviations" bullet, and adds a "Final design" list from what the build recorded: `primary`, `display-font`, `body-font`, `hero` and `archetype` from the `landing-meta` block of `design-system/<slug>/MASTER.md`, and the `Signature moment:` line of `RUN.md` "Design decisions". A missing source prints "not recorded". The image rule names the allowed sources (Pixabay, imported Pexels, Wikimedia Commons, The Met) from `assets.json` when it lists any, else the general rule.
- **Skip link ignored.** `layout-signature.mjs` leaves out of the button measures any link or button whose box lies outside the page (right or bottom edge at or above 0, or left edge at or beyond the page width) and any `a[href^="#"]` that is the first focusable element of `<body>` with a box outside the viewport; the signature of a page without a skip link is unchanged.
- **Duplicated `_headers` paths warn.** A new static report item, `headers-duplicate-paths` (area security, OWASP A02 Security Misconfiguration), warns when `dist/_headers` has two or more blocks with the same path pattern, naming the pattern and the line numbers, with the fix "merge them into one block: Cloudflare Pages may apply only one of them". A file without duplicates passes; a site without `_headers` is `na`.

## Capabilities

### Modified Capabilities

- `prospect-landings`: the kit after every prospect build, formatted, describing the built page.
- `landing-report`: the `headers-duplicate-paths` item.
- `landing-generation`: the layout signature ignores the off-screen skip link.

## Impact

- Code: `scripts/new-landing.sh`, `scripts/prospect.mjs`, `scripts/layout-signature.mjs`, `scripts/report/headers.mjs` (parser keeps line numbers), `scripts/report/checks-headers.mjs` (or where the static header items live), `scripts/report/` item list.
- Docs: CLAUDE.md ("Prospect landings", "Landing report"), `docs/prospect.md`, `docs/status.md` at the end.
- Tests: `tests/prospect*.test.mjs` (kit text and formatting), the report header tests (duplicate blocks warn, single block passes), a layout-signature fixture or unit test for the skip link, a `new-landing.sh` test if one covers the post-run steps (stubbed `claude`).
- No site is rebuilt. Existing `layout-signature.json` files stay as they are; a site's signature changes only the next time it is measured. fisioterapia-ribera's hand-written `SALES.md` is regenerated by the new kit in this change.
