# scripts

Automation scripts for the pipeline.

- `setup-agent.sh`: installs and verifies the agent tooling (`npm run setup:agent`, `npm run setup:verify`).
- `qa.mjs`: the QA pipeline behind `npm run qa` and `npm run qa -- --site <slug>` (`node scripts/qa.mjs --help`). Its modules live in `qa/`: `config.mjs` (defaults and validation of `qa.config.json`), `server.mjs` (build, `astro preview`, static server, page discovery), `browser-checks.mjs` (code that runs inside the page), `lighthouse.mjs` (also stores the performance detail per preset for the report), `impeccable.mjs` (CLI runner and JSON parser), `report.mjs` (Markdown report), `site.mjs` (paths for `--site`) and `privacy.mjs` (the per-page privacy record: cookie names and domains, storage keys and third-party hosts, never values) and `scene-checks.mjs` (the 3D checks for pages with `[data-scene]`: reduced motion, no JavaScript, runtime errors, Three.js chunk budget; Chromium runs with software WebGL).
- `landing-report.mjs`: the security (OWASP Top 10:2025) and performance report behind `npm run report` (`node scripts/landing-report.mjs --help`; `--site`, `--url`, `--external-links`, `--only static|live`, `--skip`, `--qa`, `--summary <dir>` for the CI comment). Modules in `report/`: `config.mjs` (defaults and validation of the `report` section of `qa.config.json`), `items.mjs` (item model, counts, verdict), `owasp.mjs` (the category table), `headers.mjs` (Cloudflare `_headers` parser, CSP evaluation), `checks-headers.mjs` (header items, static and live), `html.mjs` (small HTML scanner), `dist-scan.mjs` (private files, mixed content, SRI, links, forms, inline scripts), `source-scan.mjs` (injection sinks and secrets), `mask.mjs` (the only way a secret reaches an output), `audit.mjs` (`npm audit`), `perf.mjs` (QA detail with the timestamp guard, weights of `dist/`), `live.mjs` and `http.mjs` (deployed URL checks), `links.mjs` (outbound links), `legal.mjs` (the `legal` area: cookies and trackers, third-party hosts, legal pages, price claims), `legal-rules.mjs` (tracker hosts, cookie-name patterns, market rule sets, price-claim patterns and the `legal` config section) and `render.mjs` (Markdown).
- `render-poster.mjs`: `--page <path> --scene <name> --out <file> [--site <slug>] [--width 1600] [--progress 0.4] [--no-build]` builds and serves the project, loads the page in Chromium with software WebGL, scrolls the scene to the progress and saves the canvas as JPEG/PNG; with `--site` it records the file in `assets.json` as `source: "self"`.
- `validate-pattern.mjs`: validates `patterns/*.md` sheets (`npm run validate:patterns`, `node scripts/validate-pattern.mjs --help`).
- `validate-archetypes.mjs`: validates `design-archetypes/*.md` (`npm run validate:archetypes`); `lib/archetypes.mjs` holds the closed signal and trait vocabularies, the front matter parser and the catalog loader.
- `pick-archetypes.mjs`: `--site <slug> [--refs a,b] [--top N] [--json]` ranks archetype blends from the `Signals:` line of `PROPOSAL.md` (or `brief.json`) and the reference sheets, skipping blends other sites use; the scoring is documented in its header.
- `layout-signature.mjs`: `--site <slug> [--write] [--dist <dir>]` measures the built home page (coarse layout features and viewport-slice hashes; features documented in its header, model and weights in `lib/layout-core.mjs`) and stores `sites/<slug>/layout-signature.json`.
- `brief.mjs`: `init|validate|missing|summary|import` for the customer brief `sites/<slug>/brief.json` (`npm run brief`, `node scripts/brief.mjs --help`); the schema and validator live in `lib/brief-schema.mjs`.
- `mcp/server.mjs`: the local MCP server over stdio for agents (`npm run mcp`; modules in `mcp/`, guide `docs/agent-interface.md`). `lib/claude-stream.mjs` turns `claude -p` stream-json output into the readable run log and records the run usage.
- `new-site.mjs`: scaffolds `sites/<slug>/` from the starter (`npm run new-site -- <slug>`, `node scripts/new-site.mjs --help`); `--langs en,es [--lang <default>]` makes a multi-locale site on Astro's i18n routing (config block, a page per locale, `src/i18n/ui.ts`, language switcher). `lib/i18n-site.mjs` reads that setup back (config, dictionary, hreflang and switcher markup) for `check-landing`.
- `export.mjs`: `--site <slug> --out <dir> [--no-brief] [--no-lockfile] [--record <https-url>] [--dry-run]` writes a standalone repository for one site (`npm run export`, `node scripts/export.mjs --help`, guide `docs/export.md`): the site at the root, the scripts QA, the report and the deploy need, a pinned `package.json` and lockfile, a one-site GitHub Actions workflow, a README and `docs/factory/`. Modules in `export/`: `closure.mjs` (follows relative imports from the entry points and fails on an import outside `scripts/`), `package.mjs` (versions from the factory lockfile, tooling, wrangler only when the target can use it), `files.mjs` (what is copied and what never is), `readme.mjs` and `templates/` (`ci.yml`, `README.md`). `--record` writes `sites/<slug>/EXPORTED.json`, after which `changed-sites.mjs` skips the site.
- `revise-landing.sh`: `<slug> --feedback <file> [--model M] [--max-attempts N]` (`npm run revise`, `scripts/revise-landing.sh --help`, guide `docs/revise.md`): one recorded revision round on a built landing through `claude -p "/revise-landing ..."`; refuses a transferred site; the exit code follows the `Result:` line of `sites/<slug>/REVISION.md`. `revisions.mjs` (`preflight|next|validate|attach-usage|show`) is its helper for `sites/<slug>/revisions.json` (`lib/revisions-schema.mjs`).
- `sync-export.mjs`: `--site <slug> --into <clone> [--brief|--no-brief] [--no-lockfile] [--dry-run]` mirrors a fresh export of an exported landing into a clone of its repository (add, change, delete; keeps `.git`, ignored paths, the lockfile and the README export line) and prints the files; never commits or pushes. `transfer.mjs record --site <slug> --to <github-owner>` records the transfer of the repository to the customer in `EXPORTED.json`; `lib/export-record.mjs` reads the record (`isTransferred`, repository URL normalization). `handoff.mjs transfer-plan` prints the transfer checklist.
- `changed-sites.mjs`: prints the JSON list of sites CI must build and deploy (`node scripts/changed-sites.mjs --help`); `lib/sites.mjs` holds the shared slug rule and site listing; a site with `EXPORTED.json` is never listed. `lib/proxy.mjs` is the outbound proxy helper (re-exec with `NODE_USE_ENV_PROXY`, Playwright proxy option) shared by the report, `check-landing`, `find-images`, `ai-images`, `preflight` and the analyze-reference skill.
- `new-landing.sh`: one command per landing (`npm run new-landing -- <slug> --niche "..."`, `scripts/new-landing.sh --help`): preflight, `new-site`, `npm install`, then `claude -p "/new-landing ..."`; the exit code follows the `Result:` line of `sites/<slug>/RUN.md`. `NEW_LANDING_SKIP=preflight,install,final-check` skips steps (tests).
- `preflight.mjs`: checks registry.npmjs.org, commons.wikimedia.org and upload.wikimedia.org (through `HTTPS_PROXY`), a Chromium for QA and a free slug; names every failure (`--slug`, `--sources commons,met` adds collectionapi.metmuseum.org and images.metmuseum.org, `--json`, `--chromium-path`).
- `find-images.mjs`: `search "<query>" [--source commons,met]` and `get <slug> <title|met:<id>>` on Wikimedia Commons and The Met Open Access (public-domain objects with images; v1.1 search, then one request per object; images resized to a web JPEG; entries keep the museum credit line); throttled, retries 429/503 with backoff, keeps CC0, public domain, CC BY and CC BY-SA, writes `sites/<slug>/assets.json`.
- `deploy.mjs`: `--site <slug> [--branch B] [--dist D] [--dry-run] [--json] [--github-output] [--rollback] [--print-config]` publishes a site's build to its target in `site.config.json` (`vercel`: REST API with `fetch`; `vps`: rsync over SSH into a release folder and an atomic `current` symlink; `shared`: rsync over SSH, or FTPS with `lftp`); Cloudflare Pages stays in the workflow's wrangler steps. Real deploys run only from CI; `--dry-run` prints the plan and changes nothing. Credentials come from the environment only (`VERCEL_TOKEN`, `DEPLOY_SSH_KEY`, `DEPLOY_FTP_PASSWORD`). Modules in `deploy/`: `config.mjs` (schema, validation, CI dispatch with `--github-output`, brief mapping with `--from-brief`), `headers.mjs` (`_headers` to `vercel.json`, Caddy, Nginx and `.htaccess`), `vercel.mjs`, `rsync.mjs`, `ftps.mjs`, `plan.mjs`, `files.mjs` and `redact.mjs`. Guides: `docs/deploy/`.
- `ai-images.mjs`: `generate <slug> --prompt "..." --as <name> [--size ... --quality ... --model ... --title ... --dry-run]` makes one request to the OpenAI Images API (`lib/openai-images.mjs`, no SDK; `OPENAI_API_KEY` from the environment only, `OPENAI_BASE_URL` overrides the endpoint), saves the image in `sites/<slug>/src/assets/images/` and appends its provenance entry (`source: "ai"`) to `assets.json`; `import <slug> <file> --generator ... --model ... --prompt ... --created ... --terms <url>` records an image made elsewhere; `import ... --subject owner` records an AI portrait of the brand owner (needs a brief with `brand.aiImages` and `brand.ownerPortrait` both `allowed`; `generate` refuses `--subject`; the prompt policy then skips only `people` and `real-person`); `count <slug>` shows the count against the cap (`qa.config.json` `aiImages.maxPerSite`, default 12). Refuses, before any request, when the brief's `brand.aiImages` is not `allowed`, at the cap, or when the prompt breaks `lib/ai-prompt-policy.mjs` (business or product names, team, customers, founder, logo, real people, results). Exit codes 0, 1 refused or failed, 2 bad usage.
- `legal.mjs`: `--site <slug> [--write|--check]` writes `src/data/legal.json` from `brief.json` (markets, required legal pages, holder, privacy contact, data processing, hosting, third-party hosts of the build, `pending` values) for the starter's legal components; `--check` exits 1 when it is stale, no market writes nothing. Templates support compliance and are not legal advice (`docs/legal.md`).
- `credits.mjs`: `--site <slug> [--check]` writes the photo table of `CREDITS.md` between markers (plus the "Provided by the customer" and "AI-generated images" tables) and `src/data/credits.json` from `assets.json`.
- `check-landing.mjs`: `--site <slug> [--refs urls] [--json]` runs the final landing check (credits, photo reuse, tokens, text contrast of the standard token pairs, diversity, layout diversity against the other sites' layout signatures, scene posters, AI image provenance and disclosure, copy originality). Photo reuse is a heuristic: it counts references to each imported photo in `src/` (imports bind names; each use of the name or each path string counts), not rendered instances, and does not follow aliases.
- `section-shots.mjs`: `--site <slug> [--widths 375,768,1440] [--out <dir>] [--include-404]` serves `sites/<slug>/dist` and writes one viewport screenshot per `section[id]`, header and footer per width to `qa/<slug>/sections/` (build first). For reviewing pinned sections that full-page captures show as empty space. `404.html` is skipped unless `--include-404` is given.
