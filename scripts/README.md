# scripts

Automation scripts for the pipeline.

- `setup-agent.sh`: installs and verifies the agent tooling (`npm run setup:agent`, `npm run setup:verify`).
- `qa.mjs`: the QA pipeline behind `npm run qa` and `npm run qa -- --site <slug>` (`node scripts/qa.mjs --help`). Its modules live in `qa/`: `config.mjs` (defaults and validation of `qa.config.json`), `server.mjs` (build, `astro preview`, static server, page discovery), `browser-checks.mjs` (code that runs inside the page), `lighthouse.mjs` (also stores the performance detail per preset for the report), `impeccable.mjs` (CLI runner and JSON parser), `report.mjs` (Markdown report), `site.mjs` (paths for `--site`) and `privacy.mjs` (the per-page privacy record: cookie names and domains, storage keys and third-party hosts, never values) and `scene-checks.mjs` (the 3D checks for pages with `[data-scene]`: reduced motion, no JavaScript, runtime errors, Three.js chunk budget; Chromium runs with software WebGL).
- `landing-report.mjs`: the security (OWASP Top 10:2025) and performance report behind `npm run report` (`node scripts/landing-report.mjs --help`; `--site`, `--url`, `--external-links`, `--only static|live`, `--skip`, `--qa`, `--summary <dir>` for the CI comment). Modules in `report/`: `config.mjs` (defaults and validation of the `report` section of `qa.config.json`), `items.mjs` (item model, counts, verdict), `owasp.mjs` (the category table), `headers.mjs` (Cloudflare `_headers` parser, CSP evaluation), `checks-headers.mjs` (header items, static and live), `html.mjs` (small HTML scanner), `dist-scan.mjs` (private files, mixed content, SRI, links, forms, inline scripts), `source-scan.mjs` (injection sinks and secrets), `mask.mjs` (the only way a secret reaches an output), `audit.mjs` (`npm audit`), `perf.mjs` (QA detail with the timestamp guard, weights of `dist/`), `live.mjs` and `http.mjs` (deployed URL checks), `links.mjs` (outbound links), `legal.mjs` (the `legal` area: cookies and trackers, third-party hosts, legal pages, price claims), `legal-rules.mjs` (tracker hosts, cookie-name patterns, market rule sets, price-claim patterns and the `legal` config section) and `render.mjs` (Markdown).
- `render-poster.mjs`: `--page <path> --scene <name> --out <file> [--site <slug>] [--width 1600] [--progress 0.4] [--no-build]` builds and serves the project, loads the page in Chromium with software WebGL, scrolls the scene to the progress and saves the canvas as JPEG/PNG; with `--site` it records the file in `assets.json` as `source: "self"`.
- `validate-pattern.mjs`: validates `patterns/*.md` sheets (`npm run validate:patterns`, `node scripts/validate-pattern.mjs --help`).
- `validate-archetypes.mjs`: validates `design-archetypes/*.md` (`npm run validate:archetypes`); `lib/archetypes.mjs` holds the closed signal and trait vocabularies, the front matter parser and the catalog loader.
- `pick-archetypes.mjs`: `--site <slug> [--refs a,b] [--top N] [--json]` ranks archetype blends from the `Signals:` line of `PROPOSAL.md` (or `brief.json`) and the reference sheets, skipping blends other sites use; the scoring is documented in its header.
- `layout-signature.mjs`: `--site <slug> [--write] [--dist <dir>]` measures the built home page (coarse layout features and viewport-slice hashes; features documented in its header, model and weights in `lib/layout-core.mjs`) and stores `sites/<slug>/layout-signature.json`.
- `brief.mjs`: `init|validate|missing|summary|import` for the customer brief `sites/<slug>/brief.json` (`npm run brief`, `node scripts/brief.mjs --help`); the schema and validator live in `lib/brief-schema.mjs`.
- `new-site.mjs`: scaffolds `sites/<slug>/` from the starter (`npm run new-site -- <slug>`, `node scripts/new-site.mjs --help`).
- `changed-sites.mjs`: prints the JSON list of sites CI must build and deploy (`node scripts/changed-sites.mjs --help`); `lib/sites.mjs` holds the shared slug rule and site listing.
- `new-landing.sh`: one command per landing (`npm run new-landing -- <slug> --niche "..."`, `scripts/new-landing.sh --help`): preflight, `new-site`, `npm install`, then `claude -p "/new-landing ..."`; the exit code follows the `Result:` line of `sites/<slug>/RUN.md`. `NEW_LANDING_SKIP=preflight,install,final-check` skips steps (tests).
- `preflight.mjs`: checks registry.npmjs.org, commons.wikimedia.org and upload.wikimedia.org (through `HTTPS_PROXY`), a Chromium for QA and a free slug; names every failure (`--slug`, `--sources commons,met` adds collectionapi.metmuseum.org and images.metmuseum.org, `--json`, `--chromium-path`).
- `find-images.mjs`: `search "<query>" [--source commons,met]` and `get <slug> <title|met:<id>>` on Wikimedia Commons and The Met Open Access (public-domain objects with images; v1.1 search, then one request per object; images resized to a web JPEG; entries keep the museum credit line); throttled, retries 429/503 with backoff, keeps CC0, public domain, CC BY and CC BY-SA, writes `sites/<slug>/assets.json`.
- `legal.mjs`: `--site <slug> [--write|--check]` writes `src/data/legal.json` from `brief.json` (markets, required legal pages, holder, privacy contact, data processing, hosting, third-party hosts of the build, `pending` values) for the starter's legal components; `--check` exits 1 when it is stale, no market writes nothing. Templates support compliance and are not legal advice (`docs/legal.md`).
- `credits.mjs`: `--site <slug> [--check]` writes the photo table of `CREDITS.md` between markers and `src/data/credits.json` from `assets.json`.
- `check-landing.mjs`: `--site <slug> [--refs urls] [--json]` runs the final landing check (credits, photo reuse, tokens, text contrast of the standard token pairs, diversity, layout diversity against the other sites' layout signatures, scene posters, copy originality). Photo reuse is a heuristic: it counts references to each imported photo in `src/` (imports bind names; each use of the name or each path string counts), not rendered instances, and does not follow aliases.
- `section-shots.mjs`: `--site <slug> [--widths 375,768,1440] [--out <dir>]` serves `sites/<slug>/dist` and writes one viewport screenshot per `section[id]`, header and footer per width to `qa/<slug>/sections/` (build first). For reviewing pinned sections that full-page captures show as empty space.
